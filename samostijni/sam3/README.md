## Висновок щодо 3 сценаріїв керування ресурсами
1. **Блок `using`:** Найкраща та найбезпечніша практика. Гарантує негайне детерміноване звільнення ресурсів одразу при виході з блоку, навіть якщо виникне виняток.
2. **Явний виклик `Dispose()`:** Дозволяє звільнити ресурси вручну. Завдяки прапорцю `_disposed` повторні виклики методу є безпечними й не викликають подвійного звільнення.
3. **Робота деструктора через `GC`:** Якщо розробник забув викликати `Dispose()`, деструктор (`~ThreadPool()`) спрацьовує як "останній рубіж захисту" під час збирання сміття (`GC.Collect()`), гарантуючи звільнення системних ресурсів.

## Відповіді на контрольні запитання
1. **Що таке життєвий цикл об’єкта в .NET?**  
   Це етапи існування об'єкта: створення (виділення пам'яті та конструктор) -> використання -> виявлення втрати посилань збирачем сміття (GC) -> фіналізація (виклик деструктора) -> звільнення пам'яті.

2. **Яка різниця між керованими та некерованими ресурсами?**  
   Керовані ресурси (пам'ять об'єктів .NET) автоматично очищаються Garbage Collector. Некеровані ресурси (файлові дескриптори, сокети, дескриптори потоків) вимагають ручного звільнення через `IDisposable`.

3. **Для чого призначений інтерфейс IDisposable?**  
   Для надання стандартизованого механізму явного та негайного звільнення некерованих ресурсів.

4. **Як оператор using допомагає в керуванні ресурсами?**  
   Він гарантує автоматичний виклик методу `Dispose()` при виході із зони видимості (еквівалентно блоку `try-finally`).

5. **Навіщо в патерні Dispose використовується метод GC.SuppressFinalize()?**  
   Щоб повідомити збирачу сміття, що ресурси вже звільнені вручну і викликати деструктор (фіналізатор) більше непотрібно, що оптимізує продуктивність.

6. **Чому в деструкторі викликається Dispose(false), а в методі Dispose() - Dispose(true)?**  
   `Dispose(true)` викликається вручну й безпечно звільняє як керовані, так і некеровані ресурси. `Dispose(false)` викликається фіналізатором і звільняє **тільки** некеровані ресурси, оскільки інші керовані об'єкти на цей момент вже можуть бути знищені.
