## 1. Чому делегати корисні для створення таких утиліт?
Делегати (`Func<T, TResult>`, `Predicate<T>`, `Action<T>`) відокремлюють обхід колекції від логіки обробки конкретного елемента. Замість написання окремих циклів під кожну задачу достатньо одного узагальненого методу (`Filter`, `Map`), якому потрібна поведінка передається як параметр зі строгою перевіркою типів під час компіляції.

## 2. Як лямбда-вирази спрощують виклик цих методів?
Лямбда-вирази дозволяють записувати логіку обробки безпосередньо в місці виклику в один рядок (`p => p.Price > 1000`) без створення зайвих іменованих методів. Компілятор автоматично виводить типи параметрів із колекції, а підтримка замикань дозволяє легко використовувати локальні змінні всередині умови.

## 3. Порівняння власних методів із вбудованими LINQ-операторами

| Метод `CollectionUtils` | Аналог у LINQ | Основні відмінності |
| :--- | :--- | :--- |
| `Map<TSource, TResult>` | `Select()` | Виконується негайно (повертає `List`), тоді як `Select` працює відкладено (`yield return`) і є методом розширення. |
| `MaxBy<T, TKey>` | `MaxBy()` (.NET 6+) | Працює за аналогічним принципом: шукає об'єкт із максимальним ключем за один прохід $O(n)$, але повертає результат одразу. |
| `Filter<T>` | `Where()` | Використовує `Predicate<T>` замість `Func<T, bool>` і одразу формує новий список у пам'яті без лінивих обчислень. |
| `ForEach<T>` | `List<T>.ForEach()` | У стандартному LINQ для `IEnumerable<T>` такий метод відсутній, щоб не змішувати запити з побічними діями. |

## 5. Відповіді на контрольні запитання

1. **Переваги делегатів в узагальнених методах:** дозволяють параметризувати не лише типи даних, а й саму поведінку (фільтрацію, проекцію, дію) без втрати швидкодії та типізації.
2. **Різниця між делегатами:** `Func<T, TResult>` приймає аргумент і повертає значення; `Action<T>` приймає аргумент і повертає `void`; `Predicate<T>` приймає аргумент і завжди повертає `bool`.
3. **Поєднання generics і лямбда-виразів:** забезпечує повторне використання коду без `boxing/unboxing`, високу читабельність та перевірку типів на етапі компіляції.
4. **Коли писати власні утиліти замість LINQ:** коли потрібне гарантоване негайне виконання, специфічна бізнес-логіка (логування, метрики, обробка винятків на кожному кроці) або робота в обмеженому середовищі.
