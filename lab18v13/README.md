## Висновки
Експоненційна затримка у класі `RetryHelper` працює за формулою `initialDelay * 2^(attempt - 1)`, завдяки чому інтервал очікування подвоюється після кожної невдалої спроби (наприклад, 150 мс → 300 мс → 600 мс → 1200 мс). Це дозволяє уникнути перевантаження віддаленого сервера або заблокованого файлового ресурсу частими запитами та дає системі достатньо часу на автоматичне відновлення.

## Відповіді на контрольні запитання

1. **Які типи винятків найчастіше виникають при роботі з файлами та мережею?**  
   - **Файли / I/O:** `IOException` (загальна помилка вводу/виводу, блокування файлу), `FileNotFoundException` (файл не знайдено), `DirectoryNotFoundException` (шлях або папка не існують), `UnauthorizedAccessException` (немає прав доступу).  
   - **Мережа:** `HttpRequestException` (помилки HTTP-запитів, недоступність вузла, помилки DNS), `SocketException` (розрив з'єднання на рівні сокетів), `TaskCanceledException` / `TimeoutException` (перевищення часу очікування відповіді).

2. **Поясніть принцип роботи патерну Retry. Коли його доцільно використовувати?**  
   Патерн Retry полягає в автоматичному повторному виконанні операції, яка завершилася тимчасовою помилкою, замість негайного повернення збою користувачу. Його доцільно використовувати для тимчасових (transient) збоїв: короткочасна втрата мережі, тайм-аут API, перевантаження сервера або тимчасове блокування файлу іншим процесом.

3. **Як реалізувати експоненційну затримку між повторними спробами?**  
   Для кожної наступної повторної спроби час очікування обчислюється шляхом множення початкової затримки на степінь двійки: `delay = initialDelay * Math.Pow(2, attempt - 1)`, після чого виконання потоку призупиняється (`Thread.Sleep(delay)` або `await Task.Delay(delay)`).

4. **Для чого потрібен делегат `shouldRetry` у допоміжному класі `RetryHelper`?**  
   Делегат `Func<Exception, bool> shouldRetry` визначає політику повторів для конкретного типу винятку. Він дозволяє повторювати операцію лише при тимчасових збоях (наприклад, `IOException`, `HttpRequestException`), але одразу переривати виконання без марних спроб при критичних помилках (наприклад, `ArgumentNullException` або `UnauthorizedAccessException`).
